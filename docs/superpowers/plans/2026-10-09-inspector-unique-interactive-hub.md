# Inspector Unique Interactive Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `/inspector/` a clearly Inspector-owned visual identity and let visitors explore faithful, browser-only Edu and Pro previews.

**Architecture:** Keep the hub static. Replace the shared company shell with an Inspector-specific interface, then add isolated vanilla JavaScript modules for the Edu lesson preview and Pro topology editor preview. Reuse original Inspector-Edu cave art and the native Pro topology data shape without calling either application's backend.

**Tech Stack:** Static HTML/CSS, vanilla JavaScript, native browser file downloads, existing GitHub Pages site.

**Spec:** `docs/superpowers/specs/2026-10-08-inspector-products-and-edu-pilot-hosting.md` (the interactive-preview and independent-identity acceptance criteria added 2026-10-09).

## Global Constraints

- The canonical hub stays at `https://bstudiob.co.uk/inspector/` with `#edu`, `#pro`, and `#pilot-enquiry` destinations.
- Do not load the BStudioB global stylesheet or shared company navigation/wordmark on the Inspector page. Show BStudioB ownership only as a small footer credit.
- Avoid the BStudioB homepage and Buildy oversized editorial hero, shared rounded controls, and company product-card rhythm; avoid Tributary's flowing dark-blue/teal visual identity. Inspire has no verified production route; a dirty local app candidate shows navy particle grids, cyan/pink/purple gradients, layered preview cards, and a bottom tab bar, which are not a visual target.
- Keep the Inspector-Edu host unavailable and the macOS, Windows, and Linux Inspector-Pro releases marked in preparation.
- Edu preview is fixed, browser-only sample output: no authenticated API, shell, guest, learner account, or persistent lesson progress.
- Pro preview follows the native `Topology`/`Node`/`Link` data shape and structural validator limits; it does not run deployments or validate address configuration, routes, reachability, images, or live devices.
- JSON/YAML files are generated by this browser preview; do not imply a native-app save/export action or release download is ready.
- Preserve the existing institutional enquiry form, required privacy consent, privacy link, canonical metadata, and compatibility routing.
- No automated tests or test files are part of this change. Complete a manual rendered-browser review and interaction walkthrough without changing the app repos.

## Review Focus

- Does any global BStudioB selector or company-page motif still style the Inspector hub? Remove inherited shell dependencies and inspect the rendered route.
- Does Edu accept arbitrary commands or imply a real shell, authenticated session, host runtime, or saved completion? Keep the preview's fixed command and sample-output boundary visible.
- Do Pro structural checks claim live network validation or omit required native fields and link relationships? Match the documented Python validator's scope and language.
- Can node editing, linking, removal, reset, and file downloads fail on malformed or empty values? Keep edits browser-local and show validation feedback.
- Do demos remain usable with keyboard and narrow viewport controls, and does the pilot consent form remain legible and required?
